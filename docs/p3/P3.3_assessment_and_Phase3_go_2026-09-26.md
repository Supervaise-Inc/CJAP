## The line-185 bug was real, and it is fixed

CC's "console-encoding false-negative exit code" is now clear: lines 97 and 228 printed `max |‖v‖−1|`,
and `‖` (U+2016) and `−` (U+2212) are not in cp1252. On a legacy Windows console the final print raised
`UnicodeEncodeError` **after both outputs were written** — a success reported as a non-zero exit. That
would have fired in Phase 3, which runs this script with `--force`, and CC would have correctly read it
as a failure.

Fixed and committed: both strings are ASCII (`max abs(norm-1)`), the whole file now encodes cleanly to
cp1252, and `main()` reconfigures stdout and stderr with `errors="replace"` so **no print can ever
decide the exit code again**.

The other two items stand as logged: the `--force` guard returning 3 on a deliberate refusal (cosmetic,
after CE-12), and `check_date_index.py`'s missing `draft_queries_v1.json` — which **Phase 3 step 1
copies in**, so it resolves there.
