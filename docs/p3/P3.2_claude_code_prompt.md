Run Claude Code **in the Final Project Folder**, with the working repo's venv activated (it has torch,
sentence-transformers and the bge-base snapshot in its HF cache).

## Prompt A — P3.2 / CE-6, the full-corpus dense re-embed

```
P3.2 / CE-6 — full-corpus dense re-embed after correction batch-03.
Run scripts/build_corpus_dense.py unchanged. Do not modify it.

BOUNDARIES
- Read-only: corpus/, data/text/, data/csv/*.xlsx, corpus_snapshot.json. Never edit them.
- NOTE the script's except block unlinks CORPUS_DENSE_PATH and CORPUS_DENSE_META_PATH. Any exception
  inside its try — including a missing module — DELETES the existing matrix. Pre-flight 7 is therefore
  mandatory, not precautionary.
- Write only inside data/index/ and a new report at docs/p3/p3_2_dense_rebuild_<YYYY-MM-DD>.md.
- Do NOT run build_centroids.py, build_centroids_fullcorpus.py, or anything that rebuilds the topic
  map. Batch-03 is a correction; the topic map is not what changed.
- Do NOT edit corpus/voice/voice_card.md. A staged fix exists at
  docs/p3/voice_card_header_proposed_2026-09-25.md and must wait until after CE-12.
- Do NOT restore data/index/_archived_precorrection_2026-07-17_pilot_dense*. They were archived on
  purpose (see PRE-FLIGHT 4).
- One encoder, one dimensionality for the whole corpus. If anything forces a different model, dim,
  or backend mid-run: STOP and report.

PRE-FLIGHT — report every value, then stop if any check fails
1. config: EMBED_MODEL_ID must be "BAAI/bge-base-en-v1.5", EMBED_DIM 768, EMBED_NORMALIZE True.
   These were ratified by the Sponsor at P3.1 (bakeoff_FINAL_for_dok.md). Do not change them.
2. corpus/index/chunk_index.json: expect 1,104 documents and 9,804 chunks. Cross-check that
   corpus/index/chunks.jsonl has 9,804 lines. If either reads 8,887 or 9,865 you are looking at an
   old chunk set — STOP.
3. python scripts/verify_pin.py must exit 0 before you start. If it does not, STOP: the corpus is
   not in its pinned state and nothing built from it would be attributable.
4. data/index/pilot_dense.npy must NOT exist. It was archived because it was built on 17 July,
   before batch-03 changed 18 of the 95 pilot-subset documents; with it present the parity gate
   raises RuntimeError AFTER the whole embed completes. With it absent the script records
   sanity = "skipped (no prior pilot index)" and writes NOTHING to pilot_dense.npy (new_pilot stays
   None). Do not expect it to be regenerated. If it has reappeared, move it aside — do not delete it.
5. Model resolution: app/embeddings.py resolves CJ_EMBED_MODEL_PATH (if set and a real dir) → the
   HF cache snapshot → a hub download. Confirm which one will be used and say so. If the hub is
   unreachable on this network and no cache snapshot exists, STOP and ask for a local snapshot
   directory rather than downloading anything else.
6. Backend: report EMBED_BACKEND and whether CUDA is actually available (torch.cuda.is_available(),
   device name, free VRAM). Default is cuda_fp32 with EMBED_BATCH_SIZE 8, sized for a GTX 1650.
   If CUDA is NOT available, say so and ask before falling back — cpu_fp32 is benchmarked at
   ~0.27 chunks/s on this machine, which is hours, and the resume checkpoint is keyed on the
   backend, so a CPU run cannot later be resumed on GPU.
7. Back up the current data/index/corpus_dense.npy and corpus_dense_meta.json to
   data/index/_archived_precorrection_<their mtime date>_* before anything overwrites them.
   The script does np.save over CORPUS_DENSE_PATH; that July matrix is the rollback.

RUN
8. python scripts/build_corpus_dense.py
   Stream progress. If it is interrupted, the checkpoint resumes — do not change the model, backend
   or normalize flag between attempts, or the checkpoint is discarded and the run starts over.

VERIFY — all must hold
9. data/index/corpus_dense_meta.json:
     model_id  == "BAAI/bge-base-en-v1.5"
     dim       == 768
     n_chunks  == 9804
     backend   == the backend you ran
     pilot_parity_sanity == "skipped (no prior pilot index)"
10. corpus_dense.npy shape == (9804, 768), dtype float32, and every row is unit-norm
    (max |‖v‖ − 1| < 1e-5). Report the actual max deviation.
11. The chunk_ids in the meta match corpus/index/chunks.jsonl exactly — same set, same order.
12. (WAS WRONG, CORRECTED 26 Sep) Do NOT expect pilot_dense.npy to exist after the run — the script
    does not write it when no prior pilot index is present. Instead: confirm it is still absent, and
    report that app/embeddings.py:133 loads config.DENSE_INDEX_PATH, so the runtime index is missing
    until the team rules on it (see the runbook §7). Do not create it yourself.
13. Spot-check semantics, not just shapes: embed the query
    "What did he say about the rule of law?" with the query prefix from config, take the top 5
    chunks by cosine, and print their doc_ids and titles. They should be plausibly about the rule
    of law. If they look random, the prefix or the normalisation is wrong — STOP.

REPORT — write docs/p3/p3_2_dense_rebuild_<date>.md
14. Every pre-flight value, the backend and device used, wall-clock time, chunks/s, the verify
    results from 9–13, and the exact paths of the archived rollback files.

FLAG, DO NOT FIX
- Any pre-flight check that fails · CUDA unexpectedly absent · the model resolving to a hub
  download when a local snapshot was expected · n_chunks != 9804 · any non-unit-norm row ·
  a parity value other than "skipped (no prior pilot index)".
Report and stop. Do not "helpfully" rebuild the topic map, re-chunk, or edit the corpus.
```

## Notes for whoever runs it

- **Prompt A is the gate.** Nothing in B is meaningful if the dense matrix is wrong, and the
  cheapest place to catch that is step 13 — five retrieved titles you can eyeball.
- **The parity check being "skipped" is correct here**, not a warning. July's pilot index cannot be a
  comparator for a corpus that has since changed 156 documents.
- **After B, the next step is CE-11**, not CE-12: extend the gold set to exercise what changed —
  the merged Centenary chapters, the repaired BA031 / BA039 / BC017 / BC018, and one temporal query
  for the normalised dates. A promotion eval that does not test the change proves nothing about it.
